Oversized content

The failure mode, handled explicitly. A single atomic box taller than one whole page cannot be paginated — the engine places it on a fresh page and returns a warning rather than dropping it silently. Check the console after generating.

Oversized Content — Too Tall for Any Page

The image below is deliberately taller than the usable height of an A4 page. It is one atomic box, and no page is tall enough for it, so no pagination decision can place it as measured. There are only two honest answers, and which is right depends on the content — so the caller picks with the oversized option. Switch the control above to compare them.

scale (the default)

Shrink it to fit. The engine prefers to fill the space left on the CURRENT page rather than starting a fresh one, so the page before the image does not end up almost entirely blank — that gap is exactly the unexplained white space this project exists to remove. The floor is minFill (default 0.4): the engine will not shrink a box below that fraction of a full page just to dodge a page break, because past that point the reader loses more from the shrinking than from the gap.

Only boxes the analyzer marked scalable are eligible, which today means bare images. Text is never silently resized — a document whose type size changes wherever a page happened to end is worse than one with a page break in it.

overflow

Place it at full size on a fresh page and let it run past the page bottom, with a warning naming the box id and both heights. Correct when you would rather see the breakage than have the library quietly resize your content. Note what this costs: the page before it is left almost empty, and everything past the page edge is clipped by the viewer.

Content after the oversized box

Normal content resumes here. Under either mode the oversized box does not corrupt the flow — everything after it paginates as usual.
