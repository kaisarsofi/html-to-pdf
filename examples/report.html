Quarterly Report — Example Document

This paragraph is intentionally long enough to wrap across several visual lines, so you can see that html-to-pdf breaks pages between LINES of text rather than either cutting a line in half (the screenshot-slicing problem) or leaving a large blank gap because the whole paragraph was treated as one unsplittable block (the naive "avoid mid-content cuts" over-correction). Each line is measured individually with the browser's own layout engine, so the break point is always exactly where a line already ends.

Section One

Every table row below is marked atomic, so a row is never split between two pages — if a row doesn't fit in the remaining space, the whole row (and only that row) moves to the next page, and nothing above it is stretched or padded to compensate.

Section Two

This second block of text exists mainly to push content close to a page boundary, so that when you generate the PDF you can see the pagination engine make a real decision about where to break — packing the first page as full as it can go, instead of stopping short and leaving unexplained white space at the bottom.

Repeat: no empty gap should appear above a page break unless the next piece of content genuinely could not fit in the space that was left.
