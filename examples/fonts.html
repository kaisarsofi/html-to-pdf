Typefaces survive the trip. The three generic families map onto PDF's built-in standard 14 for free, and a real web font is embedded from the page's own @font-face rule — no configuration.

Fonts — Standard 14 and Embedded Web Fonts

Every PDF reader has Helvetica, Times and Courier built in, in four styles each. Mapping a run's computed font-family onto the right one costs nothing: no downloads, no embedded bytes. That alone covers most documents, and it is what keeps a code span monospace instead of flattening it to the body face.

The three generic families

Sans-serif text maps to Helvetica, with bold and italic.

Serif text maps to Times Roman, with bold and italic.

Monospace text maps to Courier, with bold and italic.

A real embedded font

This paragraph is set in Lora, a web font declared with @font-face in this page's own stylesheet. The library reads that rule, fetches the file, and embeds a subset of it, so the PDF shows the same typeface the reader saw on screen — not a generic substitute. Bold and italic are separate faces and are embedded separately.

Subsetting matters here: only the glyphs actually used are embedded, which is the difference between a few kilobytes per face and a few hundred.

Mixed within one line

A single line can mix all of it — serif, mono, Lora and bold sans — with every run keeping its own face, size and colour, and all of them sitting on one shared baseline.
